# DDP Baseline 知识关键点

## 进程与设备

本项目默认使用 CUDA。`torchrun` 为每张 GPU 启动一个独立进程，并注入 `RANK`、`WORLD_SIZE`、`LOCAL_RANK`。`LOCAL_RANK` 只用于当前节点的设备绑定，`RANK` 是全局编号。CUDA 使用 NCCL，CPU 使用 Gloo。只有明确传入 `--device cpu` 时才会走 CPU 路径。

真实 GPU 验证必须同时满足 `torch.cuda.is_available()` 为 `True`、`torch.cuda.device_count()` 大于 0，并且 `nvidia-smi` 能看到设备。若 CUDA 不可见，程序会直接报错，不会静默退回 CPU。

## 数据切分与复现

`DistributedSampler` 保证不同 rank 读取不同索引；每个 epoch 必须调用 `set_epoch(epoch)`，否则 shuffle 顺序会重复。本项目使用 `drop_last=True`，避免为整除 world size 而复制尾部样本，但会舍弃少量样本。数据集和 sampler 的 seed 必须明确记录。

## 梯度同步与累积

DDP 在反向传播时 all-reduce 梯度。梯度累积期间使用 `model.no_sync()` 跳过中间 micro-batch 的同步，在窗口最后一次反向时同步并执行 optimizer step。loss 除以实际窗口大小，才能保持与等效大 batch 一致；最后一个不完整窗口也必须按实际大小缩放。

## AMP 与有效 batch

CUDA AMP 由 autocast 选择低精度算子，GradScaler 缓解 FP16 梯度下溢。AMP 的收益必须通过相同模型、数据和 batch 的 A/B 实验确认。有效 batch size 等于 `每 rank batch * world size * accumulation steps`。

## Checkpoint 语义

只有 rank 0 写 checkpoint，避免多个进程争用同一路径。本实现按 optimizer step 保存，状态包含模型、优化器、scheduler、scaler、epoch、当前 epoch 内已完成 batch、`global_step`、`samples_seen` 和各 rank 的 Python/CPU/CUDA/DataLoader RNG。恢复时跳过已经完成的 batch，从中断位置继续；epoch 结束时额外保存边界状态。`checkpoint.pt` 是最新状态，`checkpoint-step-XXXXXXXX.pt` 用于保留带 step 编号的快照。所有写入都通过临时文件替换，降低中途写入留下半文件的风险。

resume 前会校验关键配置和 world size，避免用不同 batch、累积步数、数据、模型或并行规模静默改变训练轨迹。当前仍是单文件 checkpoint，不支持 FSDP/ZeRO 分片、动态 batch、streaming token 游标或多数据源采样状态。

## 排障思路

DDP hang 首先检查所有 rank 是否执行了相同次数的 collective，以及是否有 rank OOM/提前退出。loss 异常重点检查 sampler、loss 缩放、学习率和有效 batch。OOM 要区分参数、梯度、optimizer state 与激活占用。生产训练还需要保存 RNG、scheduler、分片 checkpoint，并补充 barrier、Profiler 和长稳测试。

## NPU 边界

NPU 不能直接复用 CUDA 命令。设备 API、自动混合精度和通信后端需要替换为厂商适配的 PyTorch 包与 HCCL 配置，且应单独记录软件版本和验证结果。
